# 🚀 Deploying Monster Legends Arena to Render

This project is pre-configured to deploy as a **single Render Web Service** — the
Express/Socket.IO backend serves the built Phaser frontend from the same origin,
so there's no separate frontend service and no CORS headaches.

---

## ✅ What's already configured

- `render.yaml` — Render Blueprint, defines the service automatically
- `MONGODB_URI` — pre-filled with your Atlas connection string
- `JWT_SECRET` / `JWT_REFRESH_SECRET` / `ADMIN_SECRET_KEY` — auto-generated by Render on first deploy
- Redis — **optional**, the app runs fine without it (caching just falls back to direct DB reads)
- File logging — disabled in production (`ENABLE_FILE_LOGS=false`), logs go to Render's log viewer instead
- Frontend build output (`frontend/dist`) is automatically served by the backend at `/`

---

## 📋 Step-by-step deploy

### 1. Push this project to GitHub
```bash
cd monster-legends-arena
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/monster-legends-arena.git
git push -u origin main
```

> ⚠️ `backend/.env` is in `.gitignore` and will **not** be pushed — this is intentional.
> Your MongoDB URL and secrets are instead defined in `render.yaml`, which Render reads directly.

### 2. Create the Render Blueprint
1. Go to [dashboard.render.com](https://dashboard.render.com)
2. Click **New** → **Blueprint**
3. Connect your GitHub repo
4. Render detects `render.yaml` automatically and shows you the service it will create
5. Click **Apply**

Render will:
- Run `npm run render-build` (installs backend + frontend deps, builds the frontend)
- Seed the database (300 monsters, items, quests) on first build
- Start the server with `npm run render-start`

### 3. Wait for the first deploy (~3–5 minutes)
Watch the build logs. You should see:
```
✅ MongoDB connected: cluster0...
✅ Monsters: 300 upserted
✅ Items: 50 seeded
🎮 Monster Legends Arena server running on port 10000
```

### 4. Open your game
Render gives you a URL like:
```
https://monster-legends-arena.onrender.com
```
Open it — the game loads directly, no separate frontend URL needed.

## 🐌 Free tier notes

- Render's **free web service** spins down after 15 minutes of inactivity and takes
  ~30–60 seconds to wake up on the next request. This is normal — your players will
  see a brief loading delay after idle periods.
- To avoid spin-down, upgrade to a **Starter** plan ($7/mo) or use an external uptime
  pinger (e.g. UptimeRobot hitting `/health` every 10 minutes) to keep it warm.
- Without Redis, matchmaking/leaderboards still work — they just hit MongoDB directly
  instead of a cache layer. Fine for small-to-medium player counts.

## 🛠️ Manual setup (without Blueprint)

If you'd rather configure the service by hand in the Render UI instead of using
`render.yaml`:

1. **New** → **Web Service** → connect repo
2. **Build Command:**
   ```
   npm run render-build && (cd backend && node src/data/seedDatabase.js || true)
   ```
3. **Start Command:**
   ```
   npm run render-start
   ```
4. **Environment variables** — add manually:
   ```
   NODE_ENV=production
   MONGODB_URI=mongodb+srv://factotask:Vaibhav0503V@cluster0.wmm2alz.mongodb.net/palpark
   JWT_SECRET=<click "Generate">
   JWT_REFRESH_SECRET=<click "Generate">
   ADMIN_SECRET_KEY=<click "Generate">
   ENABLE_FILE_LOGS=false
   ```
5. **Health Check Path:** `/health`
6. Deploy.

## ❓ Troubleshooting

**Build fails with "Cannot find module 'phaser'"**
→ Confirm `frontend/package.json` lists `phaser` in `dependencies` (it does by default).

**App starts but shows blank page**
→ Check build logs for Vite build errors. Confirm `frontend/dist/index.html` exists
  after build (visible in Render's build output).

**"MongoServerError: bad auth"**
→ Double-check the password in your connection string matches Atlas exactly, and
  that the database user has the correct role.

**Socket.IO not connecting**
→ Render supports WebSockets by default on all plans — no extra config needed.
  If issues persist, check browser console for the actual Socket.IO connection URL.
